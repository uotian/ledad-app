# ledad 利用・開発ガイド

[README（日本語）](../README.ja.md)

会議の理解と発言を支援する、ローカルMacアプリです。本人が内容を確認・選択し、AIが読み上げます。画面表示と発話は日本語・英語・中国語（簡体字）・フランス語に対応します。

## 起動する

自分のMacでソースコードからビルドして使います。手順は[README](../README.ja.md#セットアップ)を参照してください。生成された`build/ledad.app`をFinderから開きます。対応環境はmacOS 26以降・Apple Siliconです。Pythonの実行環境はアプリへ同梱するため、利用時にPython・Node.js・開発サーバーの導入は不要です。

初回は左下の「設定」でOpenAIとGeminiのAPIキーを登録します。キーはMacのキーチェーンに保存し、登録済みの値を画面へ返しません。初めて会議を開始するときに、マイク・システム音声へのアクセスを許可します。拒否した場合は、システム設定 → プライバシーとセキュリティ → マイク／画面収録とシステムオーディオ録音でledadを許可してください。再起動を求められた場合はアプリを開き直します。

設定では表示言語・文字サイズとAPIキーを変更できます。表示設定は次回起動にも引き継ぎます。外観はライト（カフェモカ）とダーク（濃い茶色）、システム（OSの設定に追従）を選べます。

## 使い方

### 会議に参加する

ChatはGPT-6.1-Sol（推論量low）を使い、今の話の要点・理由・不明点を短く説明します。候補生成などはGPT-6 Luna（推論なし）です。開発時は相談用モデルを`OPENAI_CONSULTATION_MODEL`、その他を`OPENAI_MODEL`で変更できます。Solの単価は[OpenAI公式モデルページ](https://developers.openai.com/api/docs/models/gpt-6.1-sol)を参照してください。新規会議の概算料金にはSolも含めますが、Solの単価を持たない既存会議では、その利用分は未算出になります。

ホームで音声入力と言語を設定し、「会議を始める」でそのまま開始します。PDF・PPT・画像・TXT・Markdownの資料は任意です。Askに聞きたいことを入力すると、会議の文脈を踏まえて相手に尋ねる質問文と、指定した発話言語での質問文を作ります。会話に答えが含まれていても、質問を回答に置き換えません。説明・提案・回答を伝えたいと明示した場合は、その発言案を作ります。各候補の発話文の横にあるスピーカーボタンで直接読み上げ、同じ場所で停止・再開できます。

会議画面は、左の会話欄を広くした2列構成です。右側はTopics・You・Chat・Askをタブで切り替えます。相談の下書きや候補の編集状態は、タブを切り替えても残ります。会話分析では論点に加え、Chat向けのAIへの相談例と、Ask向けの会議の相手への質問例を作ります。名前への言及・質問・依頼も同じ会話分析で検知・整理し、Youに表示します。Askの質問例を押すと発言案を作りますが、読み上げはスピーカーボタンを押すまで始まりません。Chatは会議の流れや過去の相談を参考にLLMが返答する私的なチャットです。送信後も相談タブに留まり、質問候補の生成や音声の再生はしません。通信失敗時には再試行できます。発言ごとの質問ボタンは置かず、会話を続けて読みやすい表示にしています。

音声の本文は左端を揃え、速報は途中・確定とも発言の時刻と `Live` を表示します。録音版への差し替え後は同じ時刻と `Fixed` を表示します。途中の文字起こしが更新されても、発言の開始時刻は変わりません。

発話操作欄の「停止」とEscapeキーは発話を止め、聞き取りは継続します。同じ欄の「再開」は保持している音声位置から続けます。フッターの赤い「停止」は音声入力だけを止め、途中の回答生成・チャット返信・読み上げは継続します。フッターの青い「再開」で同じ会議の聞き取りを続けられます。停止後の緑の「終了」で会議を終了状態で保存し、記録画面へ進んで要約を自動作成します。終了後は再開できません。要約に失敗した場合は原記録を残し、記録画面から再試行できます。

「会議の言語」は、聞き取りの認識言語と読み上げに使います。日本語ではSTTに `ja-JP` を渡します。認識言語の指定は精度を助けるヒントであり、誤認識を完全に防ぐものではありません。

「聞き取り音声の入力元」は次の3つから選びます。初期値は「PCの音声＋マイク(ZoomなどのWeb会議)」で、以後は前回保存した選択を引き継ぎます。保存済みの会議はそれぞれの選択を維持します。権限が必要な場合は、音声取得時の案内に従って許可してください。

- **PCの音声＋マイク(ZoomなどのWeb会議)**：相手の声と自分の声を同時に取得し、混ぜて1系統で文字起こしします。話者は分離しません。両方の音声取得の許可が必要です。スピーカー音がマイクへ回り込むと二重に入る場合があるため、イヤホンの使用を推奨します。ブラウザでは共有元の音声を含めて共有してください。
- **PCの音声(YouTubeなど)**：YouTubeなどの動画・配信や、別アプリの音声。BraveでKickの配信を再生して聞き取る場合もこちらを選びます。PCで再生する音声をまとめて取得するため、特定アプリだけを指定することはできません。初回はmacOSのシステム設定で音声取得を許可してください。映像は送信・保存せず、ledad自身の音声は取得対象から外します。
- **マイクの音声(対面会議など)**：自分や周囲の音声。Macで選択中の入力機器を使います。仮想音声機器もMacのサウンド設定で選べます。

「聞き取りの自動停止」は会議ごとの設定で、10分・30分（初期値）・60分・90分から選びます。開始・手動再開からの経過時間で停止し、9分ごとの自動接続更新では延長しません。自動停止後も会議の記録は残り、続ける場合はフッターの青い「再開」を押します。

読み上げはMacの既定の音声出力を使います。アプリ内の出力先選択はなく、変更する場合はMacのサウンド設定を使います。

会話欄は聞き取った音声の表示に絞り、見出し・手入力の追加ボタンは通常表示しません。各発言にはLiveまたはFixedの区分を表示します。聞き取り状態の確認と操作は画面下部のフッターにまとめています。過去に手入力した発言は、そのまま表示・保存できます。

既存のマイク・PC音声の選択は引き継ぎます。旧設定の入出力デバイスIDは読み込み時に取り除き、OSの既定機器を使います。旧「手入力で確認する」で保存された会議は、読み込み時に「マイクから取得」へ移行します。過去の手入力の会話は変更しません。読み込むだけで音声取得は始まりません。

ホームへ戻るときは、発話・聞き取りを停止して編集内容を保存します。保存に失敗した場合は元の画面に残ります。フッターの赤い「停止」では会議画面に留まり、停止後の緑の「終了」で記録画面へ進みます。議事録は記録画面から作成できます。

### オンライン会議

入力と出力は別の経路です。

- 入力：相手と自分の発言を聞き取る場合は「PCの音声＋マイク(ZoomなどのWeb会議)」、相手側だけなら「PCの音声(YouTubeなど)」を選びます。設定済みの仮想音声機器を使う場合は、Macのサウンド設定で入力機器に指定してから「マイクの音声(対面会議など)」を選びます。
- 出力：Macの既定出力へ読み上げます。会議サービスの音声共有機能を使うか、Mac側で仮想音声機器を設定し、会議サービスのマイクとして選んでください。

Zoom・Teams等へ自動的に音声を送る機能や、仮想音声ドライバーの自動導入は含めていません。物理スピーカー・マイクの回り込みや、会議サービスごとの送音は利用環境での確認が必要です。

## 資料の利用

準備中・会議中に、PDF・PPT/PPTX・PNG/JPEG/WebP・TXT・Markdownを追加できます。ドラッグ＆ドロップ、ファイル選択、画像の貼り付けに対応します。PPTは端末のLibreOfficeでPDFに変換します。セットアップ時にLibreOfficeをインストールしてください。

原本はファイルごとに保存し、会議開始時に全ファイルからGPT-6 Lunaが会議共通の要約と用語集を一回生成してから聞き取りを始めます。要約は目安1,000〜3,000文字・最大6,000文字、用語は重要順に最大100件です。会議中の追加・削除では全体を再生成します。更新中は資料件数の横に進行状況を表示し、会話と保存を続けられます。追加時は生成完了まで以前の参照文・用語集を使います。失敗やAPI上限超過は画面に表示し、原本を残して再試行できます。独自の合計ページ・文字数上限は追加せず、勝手な省略・切り詰めも行いません。会話分析・Chat・Askには共通Markdown、文字起こし（Fixed・Gemini Live）と翻訳には用語集だけを渡します。共通結果のない会議は開始・再開時に生成します。詳細は[資料の読み取り](design/05-ai/10-document.md)を参照してください。

AIへの送信と会議への公開は別です。Liveの音声認識は設定でGemini APIまたはMac内のApple SpeechTranscriberを選べます。読み上げは声に応じたOpenAIまたはGemini API、Fixedの音声認識は選択したOpenAIまたはGemini API、資料の解釈・候補生成・翻訳・議事録はOpenAI APIへ送ります。私的チャットや未発話の候補は、議事録の材料には含めません。

旧Presenterの会議・資料・原稿・発話記録は保存形式を維持して読み書きします。既存の会議は通常の会議画面で開けます。発表原稿の編集・自動読み上げ・スライド共有は廃止しました。

## データと利用記録

アプリ名・内部ID・保存先はledadに統一しています。旧版の会議データは移行せず、新しい保存先で開始します。APIキーは`jp.ledad.desktop`のキーチェーンだけを使用し、旧名の保存先は参照しません。

| 対象                               | 保存先・扱い                                               |
| ---------------------------------- | ---------------------------------------------------------- |
| APIキー                            | macOSキーチェーン、サービス名`jp.ledad.desktop`            |
| 会議・資料・聞き取り・私的チャット | `~/Library/Application Support/jp.ledad.desktop/sessions/` |
| AI利用記録                         | 同じアプリ専用フォルダの`usage/`                           |
| エラー記録                         | 同じアプリ専用フォルダの`logs/errors.jsonl`                |
| 表示設定                           | アプリ内のWebViewのローカル設定                            |
| 入力・出力音声ファイル             | 永続保存しません。再生中の音声はメモリ上に保持します       |

ホームの履歴は作成日時の新しい順に並び、最初の発言日時と、最初から最後の発言までの経過時間を表示します。会議を開くだけでは日時や順序は変わりません。準備中のデータは残しますが、一覧と件数には含めません。

会議はホームから削除できます。「すべて削除」は一覧に表示しない準備中も含めて削除し、確認画面に削除対象の総件数を表示します。資料と会議記録も削除します。本文を含まないAI利用記録は、会議の削除後も残ります。保存期間による自動削除はしません。

API詳細にはリクエスト・応答・エラー本文を保存し、会話・資料・生成文が含まれる場合があります。既知の認証情報はマスクし、バイナリ本体は省きます。会議を削除すると関連するAPI詳細も削除します。本文の保存条件・保持期間は[設計課題 Q-04](design/99_課題.md#q-04-api本文の保存方針)で検討中です。

AI利用記録には、処理ID・会議ID・モデル・処理種別・日時・結果・取得できたトークン数・音声秒数を残します。未取得は`null`で、0とは区別します。キャンセル済みでもAPI側で処理・課金される場合があります。

エラー記録には日時・会議ID・表示メッセージ・発生箇所を残します。Fixの失敗は、文字起こし・Liveとの対応確認・翻訳の段階と、対応するAI利用記録ID・音声秒数・文字数・一致率も記録します。診断ログにはAPIの応答本文や音声・会話本文を追加保存しません。別途保存されるAPI詳細の扱いは、[利用記録](design/05-ai/01-usage.md)を参照してください。ログは約2 MiBごとに切り替え、現行と過去2ファイルを保持します。会議画面のエラー表示は、閉じても記録が残ります。ローカルサービスへ接続できない場合に備え、直近100件の表示エラーをWebViewのローカル設定にも保存します。

会議画面右上の合計API料金をクリックすると、API履歴を開きます。処理ごとの利用量とリクエスト・応答の詳細を確認できます。API履歴のタイトル横でOpenAI・Geminiを切り替えます。初期値はOpenAIです。左下のリンクから、選択した提供元の課金画面を開きます。Macアプリでは既定のブラウザ、ブラウザ版では別タブで開きます。リンク先で表示されるアカウント・組織・プロジェクトは、ブラウザのログイン状態に従います。

聞き取りは送信済みPCMの秒数と、APIから届いた応答別の利用量を記録します。応答単位のトークン数を接続全体の請求量として合算しません。読み上げの生成秒数と、実際に再生した秒数も別です。会議画面には概算料金を表示し、詳細なJSONは上記の`usage/`フォルダに保存します。

議事録は実際の聞き取りと、再生完了を確認した発話区間だけを使います。中断した最後の区間は途中まで聞こえている可能性があるため、全文を話した扱いにはしません。Markdownとして保存できます。

## 開発する

必要なものはNode.js 22以降、uv、Rust、Xcode、LibreOfficeです。取得・導入手順は[README](../README.ja.md#セットアップ)を参照してください。Python 3.13と依存パッケージはuvが`backend/uv.lock`に従って準備します。

```sh
npm ci
npm run app:dev
```

開発起動時だけ、ルートの`env.local`または`.env.local`にある`OPENAI_API_KEY`と`GEMINI_API_KEY`をキーチェーンへ取り込みます。キーのファイルと値はアプリへ同梱しません。

```sh
npm run app:build
```

初回ビルド前に、Xcodeの「Settings」→「Accounts」でApple Accountを登録し、自分のTeamの「Manage Certificates」→「＋」→「Apple Development」から開発用証明書を作成します。個人のMacでの開発には無料のPersonal Teamを使えます。証明書と秘密鍵はログインキーチェーンに保存し、再ビルド時も同じTeamのものを使います。

静的画面・ローカルサービス・Swiftの音声取得モジュールをビルドし、Apple Development証明書による署名と署名検証まで行います。成功すると、起動用の`build/ledad.app`を最新版に差し替えます。アドホック署名・自己署名から切り替えた直後は、一度だけ録音権限の登録し直しや、APIキーへのアクセスの「常に許可」が必要になる場合があります。第三者への配布に必要なDeveloper ID署名・公証は含みません。開発用証明書が複数ある場合は、`APPLE_SIGNING_IDENTITY`に使う証明書の名前またはSHA-1ハッシュを指定します。

APIキーのキーチェーン許可は録音権限とは別の判定です。自己署名のローカル証明書では、アプリの内容が変わるとキーチェーンのpartition IDも変わり、「常に許可」を選んでも再確認が必要になる場合があります。再ビルド後もこの許可を維持するには、Appleの開発用証明書など、同じTeam IDで判定される署名を使用します。

Tauriの生成先は標準の`src-tauri/target/`を使い、完成したアプリを`build/ledad.app`へコピーします。`build/`はGitの管理対象外です。

ブラウザで画面・AI処理を確認する場合は、`npm run dev`だけで画面とローカルAPIが一緒に起動します。[開発画面](http://127.0.0.1:3000)を開いてください。画面とサービスのコード変更は自動反映され、Ctrl+Cで両方を終了します。保存先は`.data/`です。Macの音声取得や権限を確認するときは`npm run app:dev`を使います。本番アプリはこのHTTPサーバーを利用しません。

## コードの見方

| 場所                                     | 役割                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `src/app/`                               | 静的ページの入口。ホーム・会議                                                                    |
| `src/components/home/`                   | モード選択と会議一覧                                                                              |
| `src/components/setup/`                  | ホームの会議設定。`documents/`は資料                                                              |
| `src/components/meeting/`                | 会議画面。`conversation/`、`candidates/`、`chat/`、`presentation/`、`controls/`が画面の領域に対応 |
| `src/components/records/`、`settings/`   | 記録、設定                                                                                        |
| `src/hooks/`                             | 会議操作、保存、候補生成を画面につなぐ処理                                                        |
| `src/lib/audio/`                         | 聞き取り・読み上げ・停止再開・音声利用量                                                          |
| `backend/ledad/ai/`                      | OpenAI・Gemini、プロンプト、用途別のAI処理                                                        |
| `src/lib/session/`                       | 会議の型・初期値・資料の公開方針・記録出力                                                        |
| `backend/ledad/meeting/`                 | 会議の型、開始・終了・候補・相談・再認識の状態変更、資料の公開方針、料金                          |
| `backend/ledad/storage/`                 | 会議・利用記録・診断のローカル保存                                                                |
| `backend/ledad/service.py`、`transport/` | アプリの操作窓口と、標準入出力・開発用HTTP                                                        |
| `src/styles/`                            | 画面別のスタイルと共通テーマ                                                                      |
| `src-tauri/src/`                         | Macのウィンドウ、IPC、キーチェーン、子プロセス管理                                                |
| `native/`                                | マイク・システム音声の取得とPCM変換                                                               |
| `tests/`、`backend/tests/`               | TSの画面・音声・保存順序と、Pythonの会議・AI・保存・通信のテスト                                  |

画面は1コンポーネント1ファイルです。画面から処理を追う場合は、コンポーネント → `hooks` → `lib` → Pythonの`service.py`を見てください。AI処理と、会議の開始・終了、候補や発話の記録、録音版への差し替えはPythonへ集約しています。フォーム編集、速報の追加・表示、機器の操作タイミングはTypeScriptが担当します。

`SessionWorkspace.tsx`が準備・会議・記録画面の切り替えとホームへの移動を担当します。音声停止と保存待ちは`useMeeting.ts`の`prepareClose`、保存の順序・再試行・応答待ち中の編集保持は`src/lib/session/persistence.ts`、会議の状態変更はPythonの`meeting/commands.py`にあります。

Macの終了メニューとCmd+Qは `src-tauri/src/menu.rs`、ウィンドウの終了通知と保存待ちは `useAppClose.ts` です。OS標準の終了メニューで保存待ちを飛ばさないよう、アプリの終了項目を明示しています。

本番の通信経路は、画面 → Tauri IPC → 同梱Pythonサービス → AI APIです。サービスとの通信は標準入出力のJSONで行い、localhostの待受ポートは開きません。リアルタイムSTTのWebSocket・音声送受信・再接続は`src/lib/audio/`のTypeScriptに残し、一時トークン発行と録音の再認識はPythonが担当します。

### カバレッジ

単体テストで実行した行・分岐を計測します。TypeScriptは未実行の画面・Hookも含む`src/`全体、Pythonは`ledad`全体を対象とします。E2E、Rust、Swiftの実行範囲はこの数値に含みません。カバレッジの閾値は設けず、保存・削除・キャンセルなど重要な分岐の検証を優先します。

```sh
npm ci
npm run test:coverage
npm run test:python:coverage
```

計測ツールは開発依存として管理します。TSの`@vitest/coverage-v8`はVitestと同じバージョンを使い、`package-lock.json`で固定します。Pythonの`pytest-cov`は`backend/uv.lock`で固定し、通常のuv起動時に導入します。計測ツールはアプリ実行用の依存には含めません。初回はネットワーク接続が必要です。結果は`artifacts/coverage/`に保存し、Gitには含めません。

npx playwright install chromium
npm run test:e2e
# 明示的に実APIを使う場合のみ（APIキーと利用料金が必要）

通常実行ではBackendのOpenAI・Geminiキーを空にして、環境変数やenv.localから実キーを取り込みません。AIの成功応答が必要な箇所はテスト側で模擬します。実API対象は`meeting.spec.ts`、`translations.spec.ts`、`translation-stability.spec.ts`です。

どちらも開発サーバーに`NEXT_PUBLIC_LEDAD_DISABLE_AUDIO_CAPTURE=1`を渡して音声取得を停止し、E2E専用の入力欄から会話を追加します。この設定は`next dev`でのみ有効です。既存サーバーを再利用せず、データは通常テストが`.data/e2e/`、実APIテストが`.data/e2e-real-api/`に保存します。トレース等もそれぞれ`artifacts/e2e/`・`artifacts/e2e-real-api/`へ分けます。実行前にUIの3000番（`LEDAD_UI_PORT`で変更可能）とBackendの4320番ポートが空いていることを確認してください。

音声出力はChromiumのテスト用出力です。実APIテストでは生成したWAVのデコード・再生・停止・完了を検証しますが、物理スピーカー・Macの録音権限・Apple SpeechTranscriberは別途実機で確認します。

### 表示の設定

設定 → APIキーの「声の種類」は全会議で共通です。OpenAI（Marin / Cedar）とGeminiの声を選べます。OpenAIの読み上げ料金はAPIが返す入力・出力トークン数から計算します。修正前の使用量がない履歴は未算出のままです。会議中も変更でき、次の読み上げから反映します。再生中・一時停止中の発言は元の声を保ちます。

設定からアプリの言語（日本語・English・中文（简体）・Français）と文字サイズ（S / M / L）を変更できます。Sは従来のサイズ、Mは15％、Lは30％大きく表示します。会議名のヘッダーと操作フッターは固定サイズです。サイドバーはホーム・設定のアイコン表示に絞り、文字サイズの変更で幅やアイコンは拡大しません。その場で反映し、次回の起動時にも引き継ぎます。保存済み設定がない場合は日本語・Sです。

アプリの表示言語、会議の聞き取り・発話に使う「会議の言語」、会話と発言案の参考訳に使う「翻訳先の言語」は別です。会議の言語と翻訳先はホームで設定し、会議中は固定します。表示言語を変更しても、保存済みの会話・訳文・会議名は書き換えません。会話の原文と訳文は横に並べます。Chatの新しい返答は表示言語を基本とし、Askの発話文は会議の言語、参考訳は翻訳先の言語で生成します。議事録は日本語です。macOSの権限ダイアログはOS側の表示に従います。

書き起こし中も途中の文章を翻訳し、最短400ms間隔で更新します。直前に表示した原文と訳文を次のリクエストへ渡し、途中訳は既存の表現をできるだけ保って続きを追加します。認識の訂正や意味の修正が必要な場合は変更します。前回の訳を確実に引き継ぐため、途中翻訳は同時1件とし、待機中の原文は最新のものへまとめます。確定後の翻訳も前の発言の応答を待たずに開始します。書き起こしが確定しても、確定訳が届くまではその発言の暫定訳を残し、届いた時点で差し替えます。聞き取り中の途中結果と暫定訳はそのまま保存せず、確定した会話と訳文を保存します。終了時に残っている未確定発言は、会話として残して録音の再認識へ渡します。Fixedと手入力の記録に表示する時刻は `YYYY-MM-DD hh:mm:ss`（24時間表記・端末の現地時刻）です。時刻は、Geminiが検出した発話の開始位置を日時に換算して、確定後も引き継ぎます。開始情報がない場合は最初の途中結果の受信時刻（途中結果もなければ確定結果の受信時刻）を使い、旧記録の時刻は変更しません。

Geminiを選んだ場合、発話区切りには自動VADを使います。無音判定時間はホームの詳細設定で50・100・200・300・500msから選び、初期値は100msです。指定した時間後に確定テキストが届く保証ではありません。無音がなければ発言は続きます。

### 録音による書き起こしの見直し

聞き取りは二段階で行います。既定ではまず `gemini-3.5-transcribe-live` で会話をすぐに表示し、最後の自然な発話終了または強制区切りから送信音声が15秒分たまったら、音声ストリームの終了を通知して確定を促します。画面のタイマーには依存せず、Macアプリではバックグラウンド処理の抑制も無効にしています。ホームの詳細設定で選んだFix間隔（15秒・30秒・60秒・120秒、初期値30秒）を過ぎた発言の終わりで置き換える区間を決めます。その前後の音声を少し重ねて、選択した録音用モデル（初期値はOpenAIの `gpt-transcribe`、Geminiの `gemini-3.5-transcribe` も選択可能）で再認識し、録音区間の全文を一度に翻訳します。設定 → APIキー → 聞き取り（Fixed）で変更すると、自動保存され、次のFixed処理から反映されます。原文と訳文が揃ったら、その区間の速報を一つの `Fixed` ブロックへまとめて差し替えます。Liveの発言単位には分割し直しません。日時は置き換える区間の先頭の発言時刻を使います。

Macアプリでは設定 → APIキー → 聞き取り（Live）からApple SpeechTranscriberにも切り替えられます。macOS 26以降で利用でき、会議の言語が英語なら英語モデルを使用します。途中表示と速度優先を有効にして、会話を追いやすい速さで認識します。途中結果はAppleの確定位置に達するまで訂正を受け付けます。最後の確定位置または強制区切りから入力音声が15秒分たまったら、聞き取りを継続したまま `SpeechAnalyzer.finalize(through: nil)` で処理済み音声までの確定を要求します。確定要求は同時に一つだけ実行し、聞き取り停止・会議終了時は進行中の確定要求を待ってから残りの音声の最終確定を待って保存します（最大8秒、失敗時は表示済みの会話を残します）。認識モデルは音声取得前に準備し、会話向けの処理優先度を指定しています。Apple使用時のマイク取得バッファは2048フレームにし、利用できる場合はエコー抑制・自動音量調整を使います。初回は言語モデルをMacにダウンロードするため、聞き取り開始まで時間がかかることがあります。Apple選択時のLive音声認識はMac内で行い、Fixedには従来どおり選択したAPIを利用します。Geminiへ戻すこともできます。

前後の重なりは、まず各5秒を内部の初期値にしています。後ろの音声が届く分だけ確定版の表示を待ちます。隣のブロックと同じ発言が一部重なることを許容し、重複を削るために言葉を切り落としません。重ねる長さは精度と待ち時間を確認して調整する値で、設定画面の項目は増やしません。

音声の取得は一度だけで、Liveへ送る音声をメモリ上で分岐します。追加の録音権限はなく、音声ファイルは永続保存しません。終了・聞き取り停止では未来の音声を待たず、取得済みの音声と途中の発言を処理します。終了時は再認識・翻訳の完了まで「保存中…」と表示します。再開時には新しい音声区間から始めます。

再認識や翻訳に失敗した場合、録音と発言の対応を確認できない場合はLiveの会話を残します。連続した区間が180秒を超える場合や再認識が混み合っている場合も、元の会話を維持します。録音用モデルが常に正しいとは限りません。過去の会話を読んでいる間は末尾へ自動移動せず、再認識だけで質問候補の生成や発話は始めません。

録音の再認識と、その後の翻訳では、429や一時的なサーバー・通信障害をそれぞれ最大2回まで自動で再試行します。APIから待ち時間が指定された場合は従い、指定がなければ毎回5秒待って再試行します。翻訳だけが失敗した場合、録音は送り直しません。待機中もLiveを表示し、再試行を含む全体の期限は90秒です。日次上限・利用枠ゼロ・課金関連の制限がエラーの詳細から判別できる場合は再試行しません。失敗時の利用記録には、APIが返した制限項目・上限値・待ち時間に加え、説明文から読み取れた日次上限・残高不足などの定型表現と数値を残します。説明がなかった場合と、説明があっても読み取れなかった場合を区別します。説明からの推定で再試行の判断は変えません。利用台帳にはエラー本文そのものや会話・認証情報を保存しません。API詳細には本文を保存し、既知の認証情報をマスクします。

統合前の速報の原文・開始時刻・IDはブロック内の `liveSegments` に保持し、既存の質問候補や発話からの参照を維持します。追加項目は任意で、過去の記録も読み込めます。保存済みの旧形式のFixedは自動統合せず、録音が残っていない過去の会議は再認識しません。

録音用STTと訂正後の翻訳には追加のAPI利用が発生します。録音用モデルは開発用の `GEMINI_FIX_STT_MODEL` で変更できます。

### アプリのバージョン

アプリのバージョンは `package.json` の `version` で管理します。ホームの表示とmacOSアプリのバージョンは同じ値を参照します。更新時は `npm version patch --no-git-tag-version`（必要に応じて `minor` / `major`）で `package-lock.json` も更新し、`npm run app:build` で反映します。

リリース時はRustの `src-tauri/Cargo.toml`・`Cargo.lock` とPythonの `backend/pyproject.toml`・`uv.lock` のアプリ自身のバージョンも揃えます。依存ライブラリの番号は変更しません。変更内容は[変更履歴](../CHANGELOG.ja.md)を参照してください。
