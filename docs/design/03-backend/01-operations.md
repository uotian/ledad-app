# 03.01 操作と入出力

[Backend](00-overview.md) / [通信方式](../01-architecture/01-communication.md)

会議・資料・AI・利用記録の操作を受け付け、結果またはエラーを返します。

- リクエスト形式と入力内容を検証します。
- 操作ごとの条件を確認して処理し、結果を呼び出し元へ返します。
- 生成・翻訳の結果は[会議の更新処理](../06-data/03-persistence.md)で保存します。

## 操作一覧

`<id>`は会議ID、`…`は`/api/sessions/<id>`です。

| 操作                                            | 入出力・副作用                                                 |
| ----------------------------------------------- | -------------------------------------------------------------- |
| GET `/api/config`                               | キー登録有無、モデルとプロバイダー設定。秘密鍵は返さない       |
| PUT `/api/config` / `/api/live-settings`        | Fixed / Liveプロバイダーの保存                                 |
| GET `/api/meeting-settings`                     | 新規会議の設定                                                 |
| GET / POST `/api/sessions`                      | 一覧 / 作成。作成IDを指定した再試行に対応                      |
| GET / PUT / DELETE `/api/sessions/<id>`         | 会議取得 / 全体更新 / 会議削除                                 |
| POST `/api/sessions/<id>/commands`              | commandIdとコマンドを適用しSessionを返す                       |
| POST `/api/sessions/<id>/documents`             | 資料の検証・原本保存と未生成の登録用データの返却               |
| POST `…/document-reference`                     | 全原本から会議共通の参照文・用語集を生成・保存し共通結果を返す |
| GET `/api/sessions/<id>/documents/<documentId>` | 登録済み資料の原ファイル                                       |
| POST `…/generate`, `…/consult`, `…/translate`   | 候補、私的相談、発言の翻訳                                     |
| POST `…/translate-transcript`, `…/analyze`      | 途中翻訳 / 会話分析結果                                        |
| POST `…/refine-transcripts`                     | PCMと元発言IDから再認識・翻訳結果                              |
| POST `…/minutes`                                | 終了済みで未要約の会議から要約を生成                           |
| POST `/api/live-token` / `/api/speech`          | Gemini Live用の一時認証 / 読み上げ音声                         |
| GET `…/usage`, `…/usage/<usageId>`, `…/cost`    | 会議の利用一覧・詳細・概算料金                                 |
| POST `…/usage/<usageId>/unused`                 | 完了した対象翻訳を不利用として記録                             |
| GET / POST `/api/usage`                         | 全利用台帳 / Liveの使用量報告                                  |
| POST `/api/diagnostics`                         | 画面で発生したエラーの記録                                     |

## 資料の登録

AIへの入力と生成設定は[Document](../05-ai/10-document.md)を参照してください。

### 登録と変換

1. 準備中・会議中に資料を追加します。PDF、PPT/PPTX、PNG/JPEG/WebP、UTF-8のTXT/Markdownを受け付けます。1ファイル20MiB、会議30件、PDF・テキストは200ページまでです。
2. PPT/PPTXは端末のLibreOfficeで一時PDFへ変換します。元のスライドの文字と図表を一緒に読み取るためです。変換は専用の一時プロファイル・60秒上限で行い、終了時に一時ファイルを削除します。LibreOfficeがない・変換できない場合はPDFでの追加を案内します。変換後も20MiB・200ページを上限とし、PPTXの展開後サイズは100MiBまでです。
3. 形式・サイズを検証して原本を保存し、未生成の資料として返します。Frontendは直後にSessionへ追加して保存します。ここではLLMを呼ばず、開始前の資料の入れ替えに生成費用はかかりません。

### 読み取りのタイミングと保存

- **開始前**：原本を追加・削除して保存します。通常はLLMを呼ばず、開始・再開操作で未生成なら全資料を生成してから聞き取りを接続します。「要約・用語集を作成」で明示的に生成することもできます。
- **会議中**：追加・削除を保存した直後に全資料から再生成します。複数ファイルの一括追加は全件の保存後に一回生成します。途中の登録失敗では成功した原本を保持し、共通の作成ボタンから生成を再試行できます。
- **資料構成の変更**：全資料を未生成にします。追加時は以前の参照文・用語集を後続AIに渡し、成功後に新しい共通結果へ切り替えます。失敗時も以前の結果を保持します。削除・既存原本の変更時は以前の共通結果を無効化し、後続AIへ渡しません。全資料を削除した場合は空の共通結果にし、LLMを呼びません。差し替えは新規追加と旧資料削除です。
- **失敗・上限超過**：原本と未生成状態を保持し、エラーを表示します。「要約・用語集を作成」か開始操作で全体を再試行します。開始時に失敗した場合は聞き取りを始めません。会議中の失敗では既存の聞き取りを継続します。
- **生成済み**：資料構成が変わらない間は開始・再開・再読み込みでも結果を再利用します。要約済み会議では生成しません。

Backendは生成を直列化します。原本読み取り・変換後とAPI完了後に、会議の状態と資料全体が開始時と一致することを確認します。追加・削除・会議終了後の古い応答は保存せず、削除済みデータを復元しません。保存時には最新の会話・編集を保持して共通結果と未生成フラグだけを更新します。Frontendは生成前後の状態更新を保存・コマンドと同じキューで直列化し、AI応答の待機はキューの外で行います。生成中も会話・編集を保存でき、完了時には最新の編集を保持します。成功後の応答を失っても、同じ資料構成の古い保存内容でBackendの生成済み結果を消しません。

原本は`<documentId>`に残し、共通結果は`session.json`の`documentReference`へ一つ保存します。変換用PDFは保存しません。

資料があり共通結果がない場合は未生成として扱い、開始・再開時に全原本から生成します。

## 検証とエラー

- 会議IDは保存パスの構築前にUUID形式を確認します。
- PUTでは会議ID・shareTokenと状態条件を検査します。要約済みのstatus・minutes変更や、endedからpreparingへの変更を拒否します。
- 利用詳細は会議と利用記録のsessionIdが一致することを確認します。
- 資料・PCM・本文には形式とサイズ制限があります。Fixedでは対象発言の存在・重複・修正済み状態も確認します。
- 検証失敗・アプリのエラー・プロバイダーの失敗を、表示用メッセージとstatusへ変換します。取消はstdio側で499へ変換します。

429はエラー詳細と利用記録を残し、上限到達などの原因を識別できるようにします。
