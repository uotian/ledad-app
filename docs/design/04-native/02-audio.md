# 04.02 音声取得とApple STT

[Native](00-overview.md) / [画面の音声操作](../02-frontend/03-meeting/02.03-controller.md)

マイク・PC音声を取得してFrontendへ渡し、Apple Liveの選択時はNative内で文字起こしを行います。

- 音声取得はFrontendからの要求で開始します。
- 入力元・取得ID・認識言語を検証します。
- 音声と認識結果に取得IDを付け、現在の取得に対応する結果だけを反映します。

## 入力と音声形式

| 入力           | 処理                                           |
| -------------- | ---------------------------------------------- |
| マイク         | AVAudioEngineで取得                            |
| PC音声         | ScreenCaptureKitで取得。アプリ自身の音声を除外 |
| PC音声＋マイク | 時刻を合わせて1系統に混合。話者は分離しない    |

- Frontendへ渡すPCMは16kHz・モノラル・16bitです。
- マイクはVoice Processingでエコー抑制・自動音量調整を行います。Discrete形式の複数チャンネルが返る場合も、先頭のマイクチャンネルを明示してPCMへ変換します。自動マッピングでは無音になるためです。
- PC再生音の自動減衰（ducking）は最小に設定します。エコー抑制は維持し、減衰が完全になくなることは保証しません（[Appleの説明](https://developer.apple.com/videos/play/wwdc2023/10235/)）。
- マイクの構成変更通知でエンジンが停止した場合は、最新の入力形式でtapを登録し直して再開します。開始・復帰・終了はMainActorで直列化し、終了後に届く通知では再開しません。
- FrontendがFixed用の録音バッファとGemini / OpenAI Liveへの送信を管理します。
- PC音声とマイクの混合では、スピーカー音がマイクに回り込む場合があります。
- 混合は250msの到着差を吸収し、100msごとに送出します。送出済みの時刻に遅れて届いた音声は、その部分だけを除外して継続し、欠落を画面・診断ログへ通知します（通知は最大5秒に1回）。未送出の部分は保持します。
- 2秒分の混合バッファが一時的に不足した場合は、保持中の音声を順に送って空きを作ります。音声の末尾が送出位置より2秒を超えて遅い場合、4秒を超えて先にある場合、単一バッファが2秒を超える場合は従来どおり停止します。遅延音声を現在時刻へ移して会話の順序を変えることはしません。

## Apple Live

- SpeechAnalyzer / SpeechTranscriberを使い、macOS 26以上を対象にします。
- 認識機能・言語・音声形式の利用可否を確認し、必要な認識データを準備します。
- `isFinal`、認識結果の範囲、`resultsFinalizationTime`を合わせて確定位置を判定します。
- 最後の確定位置または強制区切りから15秒分の音声がたまると、確定を要求します。
- SpeechDetectorは発話の検出に使います。

Fixedの録音区切りは[会議設定](../02-frontend/02-home/02-meeting-setting.md)で指定します。Liveの15秒区切りとは別です。

## 停止と異常終了

- Apple / OpenAI Liveまたは混合入力の通常停止では、残った認識結果・音声と終了通知を受け取ってから終了します。
- Apple Liveは入力終端までの認識結果を待ちます。OpenAI LiveはNativeの末尾音声を受け取った後にAPIの確定を待ちます（[詳細](../05-ai/27-live-openai.md)）。Geminiの単独入力は音声プロセスを停止します。
- 古い取得IDの停止要求で、新しい音声取得を止めないよう照合します。
- Frontendも取得IDを照合し、古いイベントを無視します。
- 終了通知なしで音声プロセスが終了した場合は、取得エラーを通知します。

## 検証

- `node scripts/check-native-audio.mjs`：PCM変換・混合・Apple Liveの区切りを検証します。
- 同じコマンドで、終了開始後の音声拒否、確定処理・最終認識結果を待つ終了順序、認識用バッファあふれ・混合音声の時刻欠落のエラー通知も確認します。合成音声と認識モジュールなしのAnalyzerを使い、マイク・外部APIは使用しません。macOS 27以降・Xcode 27が必要です。
- `node scripts/check-native-audio.mjs --microphone`：許可済みの既定マイクで、構成変更による停止からの復帰を5回、終了後の通知を検証します。音声の保存や外部APIへの送信は行いません。発話の認識精度は別に確認します。

## 認識言語の対応

会議の言語`ja` / `en` / `zh` / `fr`を、Appleでは`ja-JP` / `en-US` / `zh-CN` / `fr-FR`、Gemini Liveでは`ja-JP` / `en-US` / `cmn-Hans-CN` / `fr-FR`として渡します。Appleは実行時に端末上の利用可否を確認します。フランス語は保存・APIリクエストをモックで検証し、実機認識・外部APIでの音声品質は未検証です。
