# 04.01 起動と終了

[Native](00-overview.md)

ウィンドウとBackendを起動し、終了時は実行中の処理を止めて保存を待ちます。

## 起動

1. ウィンドウを非表示で準備します。
2. [ウィンドウのサイズと位置](../02-frontend/01-layout/00-overview.md#ウィンドウサイズと位置)を復元し、現在の画面内に収めます。
3. 保存領域を準備してBackendを起動します。
4. メニュー・音声・終了処理を準備し、ウィンドウを表示します。
5. KeychainからAPIキーを取得し、Backendへ渡します。

- 会議・資料の読み書きはAPIキーの取得と並行して利用できます。
- AI処理とAI設定の取得は、キーの初期化を最大30秒待ちます。
- 初期化が終わらない場合は、Keychainの確認を案内します。

## Backendの応答と異常終了

- リクエストIDで応答を対応付けます。現行実装の待機期限は通常180秒、資料参照文の生成は300秒で、超過時は対象IDの取消を送ります。AIプロバイダー側の期限とは別です。
- Backendが終了した場合は、待機中の呼び出しへエラーを返します。
- 異常終了時はアプリの再起動を案内します。

通信方式は[通信](../01-architecture/01-communication.md)、更新の再試行は[保存と更新](../06-data/03-persistence.md)にまとめます。

## 正常終了

1. ウィンドウを閉じる要求を受け、一時的に終了を保留します。
2. AI処理と音声を停止し、残った処理と保存の完了を待ちます。
3. 保存できたらBackendと音声のプロセスを停止し、アプリを終了します。

- 保存失敗時はウィンドウを残してエラーを表示します。
- 強制終了やクラッシュでは未送信の編集が失われる場合があります。
- ホームへ戻る場合も処理を停止して保存しますが、アプリは終了せず、会議の状態も変えません。

## 自動テスト

`cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`で、実際のPython子プロセスと標準入出力を使い、応答の順序逆転・途中応答・EOF・取消・接続切断・終了時の待機解除とプロセス回収を検証します。タイムアウトは仮想時計で確認し、Keychainは呼び出しません。音声プロセスの古い取得IDによる停止と、異常終了後の後始末も対象です。

このテストではTauriのウィンドウを起動しません。Cmd+Qから画面の保存待ち・終了へ進む一連のGUI操作、実際のKeychain許可画面は別途実機で確認します。Swift側の検証は[音声](02-audio.md#検証)を参照してください。

## GUIでの終了検証（2026-10-15）

最新コードの一時コピーから専用アプリ `Ledad Quit Check`（`jp.ledad.quitcheck`）をビルドし、macOS上で実際にCmd+Qを入力しました。メニュー・終了フック・保存キューは変更していません。

- **保存待ち**：準備中の会議タイトルを編集し、Pythonの保存処理だけを一時的に待機させました。Cmd+Q後もウィンドウ・アプリ・Pythonが残り、待機解除後に最新タイトルが保存され、アプリと子プロセスが終了しました。
- **保存失敗**：専用の会議ディレクトリを書き込み不可にしました。Cmd+Q後に「保存が完了しなかったため、アプリを閉じませんでした」が表示され、画面の編集内容とプロセスが残り、ディスク上の保存済み内容は変わりませんでした。
- **再試行**：書き込み権限を戻し、編集し直さずに再度Cmd+Qを入力しました。未保存タイトルが保存され、アプリとPythonが終了しました。会議は終了扱いにならず、`preparing`を保持しました。

保存先は専用のApplication Support配下です。一時コピー内だけKeychain読み込みを無効化し、APIキーを空にしてPythonの外向き接続も拒否しました。有料API、実機の録音中終了、Keychain許可画面、配布署名は検証していません。デモ用アプリ・サーバーの停止操作は行っていません。ローカルの保存イベントと結果は `artifacts/native-quit-check/` に出力しています。
