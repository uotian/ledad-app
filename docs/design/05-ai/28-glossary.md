# 05.28 認識用の用語集

[Transcribe](20-transcribe.md) / [会話分析](30-analyze.md) / [ヘッダー](../02-frontend/03-meeting/01-header.md)

## 出典と統合

STTへ渡す用語は、ドキュメント、会話分析の順に統合します。前後の空白を除去し、大文字・小文字を区別せず重複を除きます。同じ語の出典は優先順で一つだけ表示します。1語は最大50文字、全体で最大100語とし、空文字・`< >`・改行を含む語は除外します。

- **ドキュメント**：存在する資料から作成した会議共通の`documentReference.glossary`を使います。利用可能性は[資料の読み取り](10-document.md)に従います。
- **会話分析**：既存のAnalyze呼び出しで、新しい語と既存の会話用語から残す語を選び直します。資料の有効語を優先し、その重複除去後の件数を100から引いた残り枠へ収めます。追加のAI呼び出しは行いません。

Frontendのヘッダー表示とBackendのSTT入力に同じ統合ルールを適用します。出典は表示用であり、STTへは用語の文字列配列だけを渡します。「あなたの名前・呼ばれ方」は認識用の用語へ追加せず、[@You](35-mentions.md)の言及検出に使います。資料・確定会話に根拠がある同名の語は、通常の用語として扱います。

## 会話由来の根拠

AIへ`reservedTerms`（確保済みの資料の語）、`glossaryLimit`（残り枠数）、`previousGlossary`（根拠が有効な既存語と発言ID・発言時刻）を渡します。AIは既存語と`glossaryTargetIds`（今回原文で送るFix済み・手入力・再生終了済みの発言ID）から選び、残す用語全件を`term`と`evidenceId`で返します。名前の漢字・正式名称・読み・意味を推測しません。未Fix Liveや資料・引き継ぎ要約だけにある語は抽出しません。

選別では「認識を間違えやすいこと」と「最近の会話で使われていること」を同程度に重視します。固定の優先順や点数・比率は設けず、現在の話題との関連・繰り返しの利用も踏まえ、今後の認識に役立つ順に返します。新しいだけの一般語で枠を埋めません。

Backendは確定状態・原文への完全一致・既存候補または今回の抽出対象であることを検証し、予約語との重複を除いて残り枠を強制します。AIが選ばなかった既存語は付け足しません。枠が0なら会話用語は空配列です。`Analyze.glossary`に選ばれた語を保存し、引き継ぎ要約へ移った原文由来の語も既存候補に含めます。訂正・削除後にその語を含む確定原文が根拠IDで見つからなければ除外します。Frontendも遅延応答の保存時と用語表示時に根拠を確認します。旧Analyzeの用語集は空配列として読みます。

分析の入力キーには確保済み用語も含め、資料要約が同じでも用語が変われば選別し直します。選別結果そのものは入力キーへ含めず、同じ入力での要求ループを防ぎます。

確定STTにも誤認識はあり得るため、誤表記を認識ヒントに戻すリスクは残ります。認識精度・選別の質・長時間の接続更新は実音声での評価が必要です。

## 反映タイミング

- OpenAI・GeminiのLiveは用語の変更有無によらず3分ごとに接続を更新し、その時点の保存済み会議から用語を作ります。停止・再開時も最新の用語を使います。15秒の発話確定と接続更新は別です。
- 接続更新中の音声保持・末尾の確定待ち・失敗処理・利用時間記録は既存の制御を維持します。Geminiの`goAway`でも更新します。
- Fixedは要求ごとに最新の用語を使います。Apple Liveでは引き続き用語集を使いません。
- 翻訳はドキュメントと会話分析の用語を使い、プロフィールは追加しません。
