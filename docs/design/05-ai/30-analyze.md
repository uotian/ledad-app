# 05.30 Analyze（会話分析）

[AI Overview](00-overview.md) / [AIサポート](../02-frontend/03-meeting/02.02-ai-support.md)

会話に応じてTopics・@You・Chat/Askの入力候補と、[認識用の用語](28-glossary.md)をまとめて生成します。

## 基本情報

| 設定                     | 値                                                                                |
| ------------------------ | --------------------------------------------------------------------------------- |
| API                      | OpenAI Responses                                                                  |
| モデル                   | `OPENAI_MODEL`（既定`gpt-6-luna`）                                                |
| `reasoning.effort`       | `low`                                                                             |
| `store`                  | `false`                                                                           |
| 処理名                   | `meeting_analyze`                                                                 |
| タイムアウト / SDK再試行 | 120秒 / `max_retries: 0`                                                          |
| キャッシュ               | [共通条件](00-overview.md#明示キャッシュの共通条件)に従い、明示キャッシュ（30分） |

## 実行条件

- 会議が進行中で、確定発言または再生完了文がある場合に実行します。聞き取りの停止中も対象です。
- 初回は待たずに送信します。その後は前回の分析完了時刻から設定した時間だけ待ち、待機中の変更は最新の入力へまとめます。0秒（すぐに送信）では、完了後に新しい入力があればすぐ次を送ります。待機時間は引き継ぎ原文の境界に使う分析開始時刻とは別です。
- 会話・登録されたあなたの名前・表示言語・資料の参照文が前回の分析入力と同じなら送信しません。翻訳や保存状態だけの更新では再送しません。
- 同時に送る要求は一件です。分析中に会話が追加・訂正された場合は、現在の処理が完了した後に次の分析へ渡します。会話の保存完了は待ちません。
- 失敗時は設定間隔を待たず一度だけ再試行します。再試行も失敗し、待機中の更新もなければ、新しい入力変更まで再送しません。
- 登録されたあなたの名前・表示言語・資料の参照文が変わると、進行中の要求を取り消してスケジュールを作り直します。この場合も初回として待たずに送信します。
- 会議終了・画面の破棄時にはスケジュールを停止し、進行中の要求を取り消します。

実装：[実行制御](../../../src/components/meeting/analyze/useAnalyze.ts)、[送信間隔・再試行](../../../src/components/meeting/analyze/schedule.ts)。

## 入力

外部AIには次のJSONを渡します。ローカルAPIには全会話を渡し、Backendで要約済み原文の変更検知と入力の切り分けを行います。

| キー           | 内容                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------- |
| `language`     | [アプリ設定](../02-frontend/01-layout/01.01-setting.md#一般設定)の「表示言語」            |
| `names`        | [アプリ設定](../02-frontend/01-layout/01.01-setting.md#一般設定)の「名前・呼ばれ方」      |
| `documents`    | [Document](10-document.md)の`summary`                                                     |
| `conversation` | 要約へ未取り込みの原文`{id, text, timestamp}`。時刻順。今回取り込む部分と直近の会話 |
| `mentionTargetIds` | 今回言及を抽出する発言の短いID。本文・確定状態の更新を対象にします |
| `previous`     | 現在のTopics全件（根拠発言ID付き）。初回のみnull                     |

追加の入力は`handoff`（前回までの引き継ぎ要約）と`summarizeThroughId`（今回要約へ移す最後の発言ID、対象なしはnull）です。

### AI入出力の短いID

Backendで要求ごとに発言IDを`c1`、既存Topic IDを`t1`のような短い値へ変換します。`conversation.id`・`lastEvidenceId`・`evidenceId`・`summarizeThroughId`は同じ発言対応表を使います。要約済み発言の根拠IDも変換します。新規TopicはAIが`n1`などを返し、Backendが保存用UUIDを発行します。受信後に元のIDへ戻してから根拠・引用を検証し、整列・蓄積します。対応表は要求内だけで使い、保存用IDは変更しません。

### 引き継ぎ要約と直近の原文

- 引き継ぎ要約でも、取り込む出来事の人名・組織名・対象名と行動の対応を保持します。既存要約を更新するときも具体名を抽象化せず、複数人の行動・意見・評価対象を混同しません。原文の取り込み範囲を超えた補足や、曖昧な名前・指示語の推測による結び付けは行いません。
- Topicsは表示用、引き継ぎ要約は次の分析で文脈を理解するための内部情報です。経緯、人物・対象の関係、未解決点、訂正・意見の変化を6000文字以内で保持します。
- **前回の分析開始時刻−1分以降**を原文で残します。分析完了時刻や発言件数は境界に使いません。初回は全原文を分析し、次回から古い部分を要約へ移します。
- FrontendはFix済み（`correctedAt`あり）・手入力・再生終了済みの発話に`settled: true`を付けます。Liveの15秒確定だけでは要約へ取り込まず、録音によるFixを待ちます。
- 統合したFix区間は`liveSegments`の最後の発言時刻を`endTimestamp`として渡します。再生した発話は`endedAt`を使います。境界にかかる区間は分割せず、全体を原文で残します。
- 先頭から連続する、境界より古い確定部分だけを要約へ移します。未FixのLive・再生中の発話に達したら、それ以降は原文で残します。Fixが失敗して長く残る場合は原文入力も増えます。未確定内容を黙って切り捨てません。
- 一回の分析でTopics等と`handoffSummary`を同時に生成します。引き継ぎ要約には`summarizeThroughId`までを取り込み、それ以降の直近原文は含めません。次回は更新した要約と残りの原文を渡し、取り込み済み原文は外部AIへ再送しません。要約へ移す部分がなければ既存要約をそのまま保持します。
- 要約済みの範囲は発言数と原文のハッシュで検証します。訂正・削除・統合で変わった場合は引き継ぎ要約を破棄して全原文から再分析します。Topics全件はpreviousとして渡し、訂正・統合・削除の対象にします。登録名・表示言語を変更した場合も、過去の言及を抽出し直すため同様に再作成します。
- 要約・根拠ID・Topics等は成功した一つの分析結果として返し、既存の自動保存に載せます。失敗・取消時に前回の要約を進めません。処理中の原文更新は次の分析で検知します。
- 要約済み原文と同じ名前・語が出ただけでは過去の話題を末尾へ移しません。過去のTopicsは保存した根拠IDを引き継ぎ、Backendで全会話の発言時刻から整列します。言及は下記の対象別の蓄積処理で保持し、要約から新しい引用を作りません。

要約は情報を圧縮するため省略・誤解が蓄積し得ます。長時間の実会話での品質・費用・遅延は未評価です。

### @Youの差分抽出と蓄積

@Youの検知・整理もAnalyzeの同じ応答で生成します。対象発言の選択、引用検証、訂正・削除への追従、旧保存形式の移行は[言及の検知と整理](35-mentions.md)を参照してください。

### プロンプト

詳細な指示文は[analyze.txt](../../../backend/ledad/ai/prompts/analyze.txt)を正本とします。会話の概要・人名と行動の対応を保ち、複数の要点はMarkdown箇条書きで整理します。

### Topicsの差分更新

- 毎回、現在のTopics全件を`previous.topics`に渡します。AIは全体のつながり・重複・分割を見直しますが、出力は更新・追加・削除だけです。古さを理由に入力から除外しません。
- `topicUpdates`は既存IDと完成形のタイトル・要約・最終根拠IDです。文章の部分差分ではありません。再開で根拠発言が変わる場合も更新します。
- `topicAdditions`は新規Topicの完成形、`topicDeletions`は不要になった既存TopicのIDだけです。初回は追加のみ、変更なしなら全て空配列です。
- 統合は一つの既存IDを更新して他を削除、分割は既存IDを一つに引き継いで他を追加します。省略されたTopicは保持し、言い換えだけの不要な更新は避けます。
- Backendが短いIDを復元して差分を反映し、全件を根拠発言時刻で整列します。既存IDの不正参照、重複、更新・削除の競合、新規IDの形式、最終根拠を検証します。失敗時は全変更を不採用とし、前回結果を保持します。
- 原文の訂正・削除・統合で引き継ぎ要約を再作成する場合も、現在のTopics全件を渡します。消えた根拠はnullで示し、AIが正しい根拠への更新か誤ったTopicの削除を返します。表示言語変更時は既存Topicも指定言語へ更新します。
- Frontendと保存形式は従来どおり完成済みのTopics全件を扱い、差分命令は保存しません。

### 入力配置とキャッシュ

指示文をdeveloper content、固定キー（`language`, `names`, `documents`）をuser contentの前方、残りの入力を後方に置きます。

会話は1発言を1ブロックにします。指示文・固定情報・各発言の末尾に`prompt_cache_breakpoint: {mode: explicit}`を付け、先頭からその位置までをキャッシュの再利用候補にします。`handoff`・`summarizeThroughId`・`previous`は会話の後ろに置きます。

## 出力

構造化JSONで返します。

| 出力                        | 指示の要点                                                  |
| --------------------------- | ----------------------------------------------------------- |
| `handoffSummary`             | 次回用の内部要約。更新対象なしは空文字 |
| `topicUpdates` | 更新する既存Topicの完成形：`id, title, summary, lastEvidenceId` |
| `topicAdditions` | 追加するTopicの完成形：同上 |
| `topicDeletions` | 削除する既存Topicの短いID配列 |
| `mentions` | 対象発言の言及・質問・依頼：`kind, summary, evidenceId, quote` |
| `suggestedQuestions`        | 本人がAIへ相談する短い質問を3個程度、少なくとも1個          |
| `suggestedMeetingQuestions` | 本人が会議相手へ尋ねる質問を3個程度。確認点がなければ空配列 |

Backendは`lastEvidenceId`が入力会話に存在することを検証し、根拠発言の時刻が古い順（同時刻は入力内の発言順）に話題を並べます。同じ根拠発言の話題はAIの配列順を維持します。不正な参照は分析失敗とし、既存の再試行処理で扱います。`lastEvidenceId`はTopicsの表示項目から取り除き、`topicEvidence`（話題ID→発言ID）として保存します。要約済みの話題も実際の発言時刻から順序を復元します。話題と発言の対応付け自体はAIが判断します。


Backendが`startedAt`（今回の分析開始時刻）・`context`（引き継ぎ要約・取り込み済み発言数・原文ハッシュ）・`topicEvidence`・`mentionSources`・`updatedAt`・`language`・`profileKey`・`inputKey`を付けて返します。これらは更新時刻と入力の整合性を管理する項目です。

### Topicsの補足文

Topicsは会話にある内容だけを要約します。AIが「誰を指すか不明」「決定か不明」「事実確認できない」といった分析上の補足や免責文を末尾に加えることは禁止します。提案・評価はそのまま記述し、決定に置き換えません。会話で明示された未定事項・確認事項は残します。

「〜という発言があった」「〜との話があった」「〜と述べた」など発言の存在を説明する文も省き、内容を直接書きます。意見・提案・決定の区別や話者の区別が必要な場合に限り、最短の表現を添えます。

会話の実況ではなく、内容を直接読める短いメモとして書きます。「話し手は」「通話相手は」「参加者は」といった形式的な主語は省き、要約する内容に登場する人名・組織名・対象名は残します。具体名を「人物」「配信者」などに置き換えず、誰が・誰に・何をしたかを保ちます。特定の人物への評価・行動を一般論に変えません。名前の繰り返しだけは、対応が明確な範囲で省略できます。
