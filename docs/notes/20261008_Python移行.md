# Python中心のledadへの移行

## 目標

Reactは表示・入力・承認、PythonはAI・会議の進行・保存、TauriとSwiftはMacとの接続を担当する。既存のUI、保存済み会議、モデル選択、資料の公開範囲を維持する。

## 実装順序と完了条件

1. Pythonサービスに既存のAI、資料、会議保存、利用記録、診断処理を移す。現在のJSON通信との互換性、取消、並行処理、エラー処理を検証する。
2. 開発用APIとMac同梱サービスをPythonへ切り替える。Python未導入のMacでも動く実行形式を生成し、署名と起動を検証する。
3. 会議の判断・処理をPythonへ集める。ユーザーとの追加相談により、リアルタイムSTTのWebSocketと音声送受信・再接続はReactから独立したTypeScript音声モジュールに残す。一時トークン発行・録音再認識・翻訳・分析はPythonに置く。Reactに残す状態は表示と操作に必要なものに絞る。
4. 旧TypeScriptサービスと重複実装を撤去し、画面から内部実装への依存がないことを検査する。移植元のテストの意図をPython側でも維持する。
5. 単体・通信・画面・Macアプリの検証を行う。録音権限と実際のPC音声は、ビルド成功と区別して報告する。

## 境界

- `backend/ledad/meeting`: 会議のデータと業務ルール。
- `backend/ledad/ai`: プロンプト、AI処理、プロバイダー接続。
- `backend/ledad/storage`: 会議・利用記録・診断のローカル永続化。
- `backend/ledad/transport`: 標準入出力と開発用HTTP。業務判断を置かない。
- 本番通信は標準入出力。APIキーはTauriのKeychainから初期化メッセージで渡し、画面やログへ返さない。
- 画面とPythonのデータ契約は互換性テストで確認する。既存データを勝手に一括変換しない。

## 作業記録

- 開始時の残り使用枠は77%。残り50%を下回る前後で確認し、未完了部分を明記して停止する。
- 作業開始前からUI・音声を含む多数の未コミット変更がある。それらを維持し、移行に必要な変更を追加する。
- Pythonへの移行、旧サービスの撤去、Macアプリへの同梱を完了。最終確認時の残り使用枠は64%。実機のPC音声取得については、下記の未確認事項を残す。

## 実装した分担

| 担当                 | 処理                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Python               | 解析、翻訳、相談、候補、Insights、議事録、音声生成、STT用一時トークン、録音再認識、資料抽出、公開範囲の判定、保存、利用記録、概算料金、診断 |
| Pythonの会議コマンド | 開始・終了・復元、候補の登録と見送り、発話の記録、録音版への差し替え、相談の状態変更、議事録の保存                                          |
| TypeScript           | フォーム編集、速報の追加・表示、画面の非同期操作、保存順序、音声の送受信と再接続、録音バッファ、再生・停止                                  |
| React                | 画面の構成、入力、表示、確認・承認操作                                                                                                      |
| Tauri / Swift        | アプリの起動・終了、Keychain、ファイル操作、macOSの音声取得                                                                                 |

リアルタイムSTTはReactから独立した`src/lib/audio/live-transcription.ts`に置く。PythonのAI機能を増やす場合は`backend/ledad/ai`と`meeting`を拡張し、既存のWebSocketや画面を作り直す必要はない。端末の操作タイミングと速報の更新は引き続きTS側にあるため、全ロジックをPythonに移した構成ではない。

`src/lib/session/persistence.ts`が保存とコマンドを直列化する。Python応答を待つ間の編集は応答へ再適用し、通信失敗時は同じ操作IDで再試行する。Pythonは状態と操作IDを同じファイルへ原子的に保存し、二重実行を防ぐ。これは現在の単一の編集画面を前提とし、複数端末からの同時編集を提供する仕組みではない。

旧`src/lib/ai`、`src/lib/server`、`src/service`とサーバー専用Insights実装は撤去した。移植元は作業前の変更も含め、ローカルの`artifacts/migration-backup/typescript-before-removal.tar.gz`に退避している。

## 検証結果

- TypeScript: 18ファイル・70テスト成功。保存順序、応答待ち中の編集、通信失敗後の再試行、旧音声モジュールの動作を含む。
- Python: 93テスト成功。会議ルール、公開範囲、資料抽出、料金、保存、取消、HTTPの接続制限、実SDKの通信形式、再試行を含む。
- ESLint、TypeScript型検査、Ruff成功。
- 画面E2E: 全21件を確認。全体実行で20件成功し、Presenterの1件はAskタブを開くテスト操作に直して再実行成功。共有PDF、相談、候補、発話の停止・完了、終了・再開、議事録まで検証した。
- 実API: PythonのOpenAI解析、Gemini音声生成、一時トークン発行から、TSのWebSocketによる生成音声の文字起こしまで成功。検証用の合成音声・会話を使用した。
- 既存の89会議・14,869利用記録を新しいデータモデルで読み取り検証した。一括変換や書き直しはしていない。
- Macアプリ: `npm run app:build`成功。Python実行環境を同梱した約60.65MiBのアプリを`build/ledad.app`に生成し、アドホック署名の検証に成功した。
- 同梱実行ファイル: 隔離した一時保存先で起動、JSON通信、作成・保存・削除、会議コマンド、操作IDによる二重実行防止、料金スナップショットを確認した。
- 移行後のネイティブアプリを起動し、ホームで既存会議の一覧が表示されることを確認した。その後の最終修正は同梱実行ファイルの検証で確認しており、起動中のアプリには再起動後に反映される。

## 残る実機確認

PCの音声取得ではmacOSの「画面収録とシステムオーディオ録音」の許可に関するエラーが観測され、今回の作業では実際のPC音声を継続して聞き取り・翻訳できたことまでは確認していない。ビルド成功、合成音声によるWebSocket検証、ブラウザE2Eとは分けて扱う。物理マイク・スピーカーも自動テストの確認範囲には含めない。

配布用のDeveloper ID署名・公証は今回の移行には含めない。現在のビルドはこのMacで使用するためのもの。
